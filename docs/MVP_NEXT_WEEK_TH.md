# แผน MVP สัปดาห์หน้า: จาก Portal สู่รายงานจริงหนึ่งชิ้น

## เป้าหมายเดียว

ผู้ใช้ Pilot ล็อกอินจาก PSU Data Hub แล้วเปิด **รายงานจริงหนึ่งรายงาน** ที่รวม
ข้อมูลจากอย่างน้อยสองหน่วยงานได้ภายใน 2 นาที โดยไม่ต้องรู้จัก Iceberg, Trino,
NiFi หรือ schema

รายงานแรกต้องตอบคำถามบริหารเพียงหนึ่งข้อ ห้ามเริ่มจากการนำข้อมูลทั้ง
มหาวิทยาลัยเข้าระบบ

## สิ่งที่ต้องตัดสินใจก่อนเริ่ม

- คำถามบริหารหนึ่งข้อและผู้รับผิดชอบคำตอบ
- แหล่งข้อมูลสองแหล่ง และ Data Owner ของแต่ละแหล่ง
- คีย์กลางที่เชื่อมกันได้โดยไม่ใช้ข้อมูลส่วนบุคคลเกินจำเป็น
- นิยามตัวเลข 3–5 ตัวบนรายงาน
- รอบเวลาอัปเดตและวันที่ข้อมูลมีผล
- รายชื่อผู้ใช้ Pilot แบบระบุตัวบุคคล 10–20 คน
- ช่องทางช่วยเหลือและผู้รับเรื่องในช่วง Pilot

ถ้ารายการใดไม่มีเจ้าของ ให้ถือว่ายังไม่พร้อมนำข้อมูลจริงเข้า ไม่ใช่ปัญหาที่
แก้ด้วยการเพิ่มเครื่องมือ

## แผนห้าวันทำการ

### วัน 1 — ล็อกนิยามและทำข้อมูลสังเคราะห์

- เขียนนิยามตัวชี้วัดร่วมกับ Data Owner
- สร้างไฟล์ข้อมูลสังเคราะห์ที่มีโครงสร้างเหมือนแหล่งจริง
- ระบุคอลัมน์ เจ้าของ ระดับความอ่อนไหว และเงื่อนไขคุณภาพ
- ทดลองทางเดินผู้ใช้จาก Portal ไปหน้ารายงาน

### วัน 2 — ทำท่อนำเข้าที่รันซ้ำได้

- นำข้อมูลสังเคราะห์ของสองแหล่งเข้า `raw`
- บันทึกเวลารับ แหล่งที่มา และรหัสรอบการนำเข้า
- ทำให้การรันซ้ำไม่สร้างข้อมูลซ้ำ
- ทำ failure path ที่บอกผู้ดูแลว่าต้องแก้อะไร

### วัน 3 — ทำข้อมูลกลางและเผยแพร่

- ทำความสะอาดและเชื่อมข้อมูลใน `curated`
- ตรวจจำนวนแถว ค่าว่าง คีย์ซ้ำ และช่วงค่าที่ผิดปกติ
- ให้ Data Owner ลงความเห็นว่านิยามถูกต้อง
- สำหรับข้อมูลสังเคราะห์สัปดาห์นี้ ให้ dev admin สร้างตารางใน `published` หลัง
  Data Owner อนุมัตินิยาม และบันทึกไว้เป็น temporary procedure จนกว่าจะมี
  publisher workflow แยก

### วัน 4 — ทำรายงานและทดสอบสิทธิ์

- สร้างรายงาน Superset หนึ่งหน้า มีตัวเลขหลักไม่เกินห้าตัว
- แสดงเจ้าของข้อมูล วันที่อัปเดต และข้อจำกัดการตีความ
- ทดสอบ `viewer`, `analyst`, ผู้ไม่มีสิทธิ์ และ direct URL
- เปลี่ยน `publishedReportsReady` ใน `portal/config.js` เป็น `true` เมื่อการ
  ทดสอบผ่านแล้วเท่านั้น

### วัน 5 — ทดลองกับคนจริงและแก้จุดหลง

- ให้ผู้ใช้ใหม่อย่างน้อยห้าคนลองโดยไม่สอนนำ
- จับเวลา: เปิด Portal → ล็อกอิน → พบรายงาน → อธิบายตัวเลขหลัก
- แก้ข้อความหรือทางเดินที่ทำให้ผู้ใช้หยุดเกิน 20 วินาที
- รอบสัปดาห์นี้ทดสอบ usability บนเครื่อง dev host/localhost เท่านั้น หากต้องให้
  ผู้ใช้เชื่อมจาก network ต้องมี TLS/authentication perimeter ที่อนุมัติก่อน

## เกณฑ์เปิด Pilot

- ผู้ใช้ใหม่อย่างน้อย 4 ใน 5 คนเปิดรายงานได้ภายใน 2 นาที
- ไม่มีผู้ใช้ทั่วไปต้องเปิดเครื่องมือทีมแพลตฟอร์ม
- รายงานระบุ Data Owner, วันที่อัปเดต, นิยาม และข้อจำกัดครบ
- Viewer อ่านได้เฉพาะ `published`; Analyst อ่านได้เฉพาะขอบเขตที่อนุมัติ
- การปิดสิทธิ์และการออกจากระบบทดสอบแล้ว
- Portal แสดงสถานะระบบจาก health probe จริง และสถานะข้อมูลจากผู้ดูแลประกาศ
- ไม่มีข้อมูลส่วนบุคคล รหัสผ่าน หรือคีย์ระบบใน HTML, JavaScript, URL และ log

## สิ่งที่ยังไม่ทำในสัปดาห์นี้

- ไม่เปิดรับไฟล์ทั่วไปจากหน้า Portal จนกว่าจะมี identity, audit trail และ
  approval workflow
- ไม่ติดตั้ง data catalog ขนาดใหญ่เพิ่มบนเครื่องนี้
- ไม่ทำ SSO แบบลวก ๆ; ก่อนเปิด Pilot ต้อง provision named local account 10–20
  บัญชีแยกจากสาม shared dev personas และทดสอบการปิดบัญชี แล้วจึงทำ PSU SSO
  เป็นงาน perimeter ถัดไป
- ไม่เปิดพอร์ต storage/catalog/query engine ให้เครือข่ายผู้ใช้
- ไม่นำข้อมูลทุก silo เข้าพร้อมกัน
