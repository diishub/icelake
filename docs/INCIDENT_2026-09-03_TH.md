# รายงานเหตุการณ์: ข้อมูลบุคลากรถูกนำเข้าระบบพัฒนา

เอกสารนี้เป็นบันทึกเหตุการณ์และร่างข้อความสำหรับแจ้ง Data Owner และผู้รับผิดชอบ
PDPA ของหน่วยงาน กรอกชื่อผู้เกี่ยวข้องในวงเล็บเหลี่ยมก่อนส่ง

- วันที่บันทึก: 3 กันยายน 2569
- ระบบที่เกี่ยวข้อง: PSU Open Lakehouse (development, เครื่องเดียว, `c:\icelake`)
- ผู้บันทึก: [ชื่อผู้ดูแลระบบ]
- สถานะ: ข้อมูลถูกลบครบแล้ว มาตรการป้องกันการเกิดซ้ำติดตั้งแล้ว

## 1. เกิดอะไรขึ้น

ระหว่างพัฒนาท่อนำเข้าข้อมูล (data pipeline) เมื่อวันที่ 1 กันยายน 2569 ได้เชื่อมต่อ
ระบบพัฒนาเข้ากับคลังข้อมูลจริงของมหาวิทยาลัย และดึงข้อมูลจาก schema
`bronze_master_data` จำนวน 47 ตารางเข้ามาเก็บไว้

ตารางส่วนใหญ่เป็นข้อมูลอ้างอิงและโครงสร้างองค์กร (รหัสคณะ ภาควิชา จังหวัด ประเภท
ตำแหน่ง) ซึ่งไม่ใช่ข้อมูลส่วนบุคคล **แต่มีหนึ่งตารางที่เป็นข้อมูลรายบุคคล**

| ตาราง | จำนวนระเบียน | เขตข้อมูลที่เกี่ยวข้อง |
|---|---|---|
| `p_admin` | 2,603 | ชื่อ-สกุลภาษาไทย, ชื่อ-สกุลภาษาอังกฤษ, ช่วงเวลาดำรงตำแหน่ง, เงินประจำตำแหน่ง |

ท่อนำเข้ามีการกรองคอลัมน์ตามทะเบียนการจัดชั้นข้อมูลของคลังข้อมูลต้นทางอยู่แล้ว
แต่ตาราง `p_admin` ไม่ได้ถูกระบุว่ามีข้อมูลส่วนบุคคลในทะเบียนนั้น จึงผ่านการกรอง
เข้ามาทั้งตาราง

## 2. ระยะเวลาและผู้ที่เข้าถึงได้

- ข้อมูลอยู่ในระบบพัฒนาระหว่างวันที่ 1 ถึง 3 กันยายน 2569 รวมประมาณ 2 วัน
- ระบบเปิดเฉพาะ loopback (`127.0.0.1`) ของเครื่องพัฒนา ไม่ได้เปิดสู่เครือข่าย
- ผู้ที่เข้าถึงได้ในทางเทคนิค:
  - บัญชีผู้ดูแลระบบของ Superset บนเครื่องนั้น
  - **ผู้ใช้ใดก็ตามที่เข้าถึงเครื่องนั้นได้** เนื่องจาก Trino ในระบบพัฒนายังไม่มี
    การพิสูจน์ตัวตน (authentication) ผู้เรียกสามารถประกาศชื่อผู้ใช้เองได้
- ไม่พบหลักฐานว่ามีการเข้าถึง คัดลอก หรือส่งออกข้อมูลโดยบุคคลอื่นนอกจากผู้พัฒนา
  แต่ระบบพัฒนายังไม่มี audit trail รายบุคคล จึงยืนยันได้เพียงว่าไม่พบหลักฐาน
  ไม่สามารถยืนยันได้ว่าไม่มีการเข้าถึงเกิดขึ้น

## 3. การลบข้อมูล

ลบเมื่อวันที่ 3 กันยายน 2569 ครอบคลุมทุกที่ที่พบสำเนา:

| ที่เก็บ | การดำเนินการ |
|---|---|
| ตาราง Iceberg ใน `polaris.raw` | ลบทั้ง 47 ตาราง |
| ไฟล์ข้อมูลใน object storage (`raw/`) | ลบทั้งหมด |
| ไฟล์ CSV ที่พักไว้ระหว่างนำเข้า (`staging/`) | ลบทั้งหมด รวมไฟล์ของ `p_admin` ขนาด 415 KB |
| NiFi content repository และ provenance repository | ล้างทั้งหมด |
| ท่อนำเข้าที่เชื่อมกับคลังข้อมูลจริง | ลบออกจากระบบ |
| รหัสผ่านเชื่อมต่อในไฟล์ตั้งค่า | ลบออก และแจ้งขอเปลี่ยนรหัส |

ไม่ได้เก็บสำเนาข้อมูลไว้เป็นหลักฐานโดยเจตนา เนื่องจากการเก็บสำเนาข้อมูลส่วนบุคคล
เพิ่มอีกชุดขัดกับวัตถุประสงค์ของการลบ หลักฐานที่เก็บไว้เป็นจำนวนแถวและรายชื่อ
คอลัมน์เท่านั้น

**ข้อสังเกตทางเทคนิคที่สำคัญ**: การลบตาราง (`DROP TABLE`) ในระบบนี้ไม่ได้ลบไฟล์
ข้อมูลออกจาก object storage โดยอัตโนมัติ ไฟล์จะค้างอยู่และยังอ่านได้ จึงต้องลบ
ไฟล์โดยตรงเพิ่มอีกขั้น ซึ่งได้ดำเนินการแล้ว และได้เพิ่มขั้นตอนลบไฟล์ค้างเป็นงาน
ประจำของระบบเพื่อให้การลบข้อมูลในอนาคตสมบูรณ์จริง

## 4. มาตรการป้องกันการเกิดซ้ำ

ติดตั้งแล้วและทดสอบแล้ว บังคับด้วยโค้ดไม่ใช่ข้อตกลง:

1. **บัญชีรายชื่อระบบต้นทางที่อนุญาต** ระบบเปิดการเชื่อมต่อไปยัง host ที่อยู่ใน
   รายการอนุญาตเท่านั้น host ที่ไม่อยู่ในรายการถูกปฏิเสธ ไม่ใช่ลองเชื่อมต่อดูก่อน
2. **บัญชีรายชื่อระบบต้องห้าม** ครอบคลุมทั้งโดเมน `psu.ac.th` และมีผลเหนือรายการ
   อนุญาต การจะเชื่อมต่อระบบจริงได้ต้องแก้ไฟล์สองไฟล์ที่อยู่ในระบบควบคุมเวอร์ชัน
   ซึ่งเห็นได้ชัดเวลาตรวจทานโค้ด
3. **บังคับตั้งแต่ตอนระบบเริ่มทำงาน** ไม่ใช่ตอนที่มีคนนึกได้ว่าต้องตรวจ ถ้า
   ตั้งค่าชี้ไประบบต้องห้าม บริการนำเข้าข้อมูลจะไม่เริ่มทำงานเลย
4. **ตรวจการตั้งค่าที่อยู่ในเครื่องมือนำเข้าโดยตรง** เพราะที่อยู่ระบบต้นทางที่
   พิมพ์ลงในเครื่องมือไม่ได้ผ่านไฟล์ตั้งค่า การตรวจเฉพาะไฟล์ตั้งค่าจึงไม่พอ
   (ข้อนี้คือช่องที่ทำให้เหตุการณ์นี้เกิดขึ้นได้)
5. **ทะเบียนควบคุมการนำเข้า** ที่บังคับให้ต้องระบุ Data Owner ฐานทางกฎหมาย และ
   ระยะเวลาเก็บรักษา ก่อนจะลงทะเบียนแหล่งข้อมูลใดได้
6. **ระบบพัฒนาใช้ข้อมูลสังเคราะห์เท่านั้น** ตั้งแต่นี้ไป

## 5. ความเสี่ยงที่ยังเหลือ

- Trino ในระบบพัฒนายังไม่มีการพิสูจน์ตัวตน อยู่ระหว่างดำเนินการแก้ไข ระหว่างนี้
  ระบบยังไม่พร้อมรับข้อมูลจริงใด ๆ
- ยังไม่มี audit trail รายบุคคล จึงยังตอบไม่ได้ว่าใครดูอะไรเมื่อไร
- มาตรการข้างต้นป้องกันการเชื่อมต่อระบบต้นทางที่ไม่ได้รับอนุญาต แต่ไม่สามารถ
  ตรวจจับกรณีที่มีผู้คัดลอกข้อมูลจริงออกมาเป็นไฟล์แล้ววางในระบบด้วยตนเอง

## 6. สิ่งที่ขอจากผู้รับเรื่อง

1. ขอให้เปลี่ยนรหัสผ่านของบัญชีฐานข้อมูลที่ใช้เชื่อมต่อคลังข้อมูล เนื่องจากรหัส
   เคยถูกตั้งค่าไว้ในระบบพัฒนาและเคยถูกใช้งานจริง
2. ขอความเห็นว่าเหตุการณ์นี้เข้าข่ายต้องรายงานตามระเบียบ PDPA ของมหาวิทยาลัย
   หรือไม่ และต้องดำเนินการใดเพิ่มเติม
3. ขอให้พิจารณาปรับปรุงทะเบียนการจัดชั้นข้อมูลของคลังข้อมูลต้นทาง ให้ตาราง
   `p_admin` และตารางลักษณะเดียวกันถูกระบุว่ามีข้อมูลส่วนบุคคล เพื่อให้ระบบ
   ปลายทางที่อ่านทะเบียนนี้กรองได้ถูกต้อง
